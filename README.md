# Scènes à Faire: an empirical method

Code, small derived outputs, and Study 1 materials for

> David G. Kamper, Mark Bartholomew, Mira Patel & Keith J. Holyoak, *Common or Characteristic? An Empirical Method for Scènes à Faire* (manuscript, 2026).

The copyright doctrine of scènes à faire denies protection to elements that are "standard, stock, customary, stereotypical, or common" in a kind of work. The project measures that factual claim. From 45,958 film plot summaries in seventeen genres it extracts characters, settings, objects, and events and computes, for every element in every genre, two quantities:

* **prevalence**, P(element | genre): the share of the genre's films that contain the element;
* **distinctiveness**, P(genre | element): the share of films containing the element that belong to the genre (Dirichlet-smoothed, α = 1).

It then tests the two measures against held-out films, against elements that courts have called scènes à faire, and, in a preregistered study (Study 1), against what people list as expected in a genre and how expected they rate particular items.

### Running the notebooks

In Google Colab, every notebook mounts Google Drive and expects the project folder at `MyDrive/DGK Lab/Reasoning Lab/DGK Lab - Scene A Faire Computational/`; change `PROJECT_ROOT` (or the candidate paths) in the first code cell to use another location. Run locally, each notebook looks for `Analysis/v4_rebuild` relative to the working directory, so start it from `Analysis/notebooks/`. The Python notebooks need pandas, pyarrow, matplotlib, scipy and networkx, plus spaCy with `en_core_web_lg` (notebooks 02 and 02b) or `en_core_web_sm` (notebooks 07c and 13); notebook 04 needs `transformers` and a GPU. The R files need `lme4`, `lmerTest`, `ordinal`, `ggplot2`, `arrow`, `jsonlite` and `rmarkdown`.

Notebooks 02b, 03b, 05, 07, 07b and 11 call a model API (Anthropic, OpenAI, Google, or Voyage). They read their keys from Colab Secrets (`userdata.get(...)`) or from environment variables; no key is stored in this repository. Their saved outputs are included, so the later notebooks run without any API call.

## What is not included, and why

* **The source corpora**, which must be downloaded from their own pages under their own terms (see "Upstream data" below).
* **Large intermediate tables** (over 50 MB, or regenerated by the notebooks): the audited corpora, the union corpus (`movies_union.parquet`), the element index, the per-film element table, the per-bin table of notebook 08, and the combination table of notebook 03c. Running the notebooks from the corpora reproduces them.
* **Study 1 participant data.** The session files, the coded responses and the human coder sheets contain participant identifiers and are not public. The tables in `Analysis/v4_rebuild/12_study1_analysis/` are aggregates.
* **Court opinions.** The opinion texts are public records retrievable from CourtListener; only the curated element lists and the triage table are included.
* **The manuscript**, which is under review.

## Preregistration

Study 1 was preregistered on OSF (https://osf.io/4azwv). The materials it cites are the release `study1-prereg` of this repository (commit `954d717`), which stays fixed. Files changed since then reflect later work; for example, the coding notebook now carries the outputs of the real run.
